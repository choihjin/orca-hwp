# 메모를 읽는 엔진 `0.8.7-p2`

2026-11-24. 사용자 승인(설계·계획). 설계는 [메모 보기 설계](../superpowers/specs/2026-11-24-memo-list-design.md).

## 문제

rhwp 0.8.7(우리 판 p1)은 메모를 쪽 그림에 그리지 않고, 메모 본문을 꺼내는 API도 없다. HWPX의 본문은 엔진이 읽지만 밖으로 나오지 않고, HWP의 본문(구역 끝의 `MEMO_LIST`)은 마지막 문단에 섞여 버려진다.

## 결정

- rhwp 0.8.7에 패치 하나(`build/rhwp-patches/v0.8.7-memo-list.diff`)를 더해 `getMemos()`를 만들었다. HWP 메모 본문 읽기는 rhwp 0.9.1의 코드를 바탕으로 했고, 메모 찾기는 문단을 담는 모든 곳(본문, 표 칸, 글상자, 캡션, 머리말, 꼬리말, 각주, 미주, 바탕쪽)을 도는 코드를 새로 썼다. 0.9.1의 `getMemoList`는 몇몇 자리를 건너뛰어 쓰지 않았다.
- 파일에 선언된 메모 수를 찾은 수와 **대조**한다. 모자라면 `missing-memo`로 알린다. 숨은 설명 안의 메모처럼 읽지 않는 자리도 이것으로 드러난다. 읽지 못한 구역은 `section-unreadable`, 읽지 못한 기록은 `bad-record`로 알린다.
- 쪽 위 강조는 엔진이 아니라 JS(`editor/engine/memo-marks.js`)가 글자 배치로 계산한다. 같은 자리의 글이 둘 이상이면 커서 좌표가 맞는 하나만 강조하고, 정할 수 없으면 강조하지 않는다. 메모가 달리지 않은 글을 강조하는 것이 빠뜨리는 것보다 나쁘다고 보았다(행정업무운영 편람 383쪽 중 200쪽에 같은 자리 글이 둘 이상 있었다).
- 확실하지 않은 범위(`ambiguous`, 예: `beginIDRef`가 0인 겹친 메모)의 메모는 강조하지 않고 기준 글도 내보내지 않는다.
- 탐색에서 선택한 HWPX 구역 파일이 ZIP에 없으면 p1과 같은 열기 오류를 반환한다. 탐색에서 빠진 구역 선언, 비어 있거나 잘린 구역 XML, HWP의 짧은 구역 스트림은 `section-unreadable`로 알린다.
- 파일의 댓글 관계(`MemoExtended`)는 읽지 않는다. 같은 글에 단 메모를 번호순으로 묶는다.
- WASM과 함께 JS 연결 파일 셋도 우리 빌드의 것을 쓴다(npm 것과 다름). `build/pins.json`의 `rhwp.patched.files`에 고정하고, `npm run vendor:rhwp`는 npm 다섯 파일을 먼저 확인한다.

## 결과 (2026-11-24)

- WASM 11,896,394 B, SHA-256 `6b8823f4c796bf806b897bcb4cae3b9e6de267ec32174e403e6fcdd2de59c4ba`(p1 11,805,164 B). 패치 안의 빌드 경로가 컴퓨터 홈 폴더를 담고 있어(p1·p2 공통) 다른 홈 폴더에서 다시 빌드하면 해시가 다를 수 있다(추정, 확인 안 함). 공개 표본 6개 739쪽의 SVG가 p1과 같다(워커 측정). 새 폴더에서 다시 빌드해 네 파일의 해시가 고정값과 같았다(워커).
- 무작위로 고른 공개 표본의 글 4,200개씩 2회(시드 2개)에서 메모가 달리지 않은 글이 강조된 경우 0건, 다른 쪽에서 강조된 경우 0건. 위치를 찾은 비율 96.7%(본문은 전부). 강조 글자는 위치별로 대조한다.
- 메모 300개(본문 2,400자)·383쪽 문서의 첫 프레임까지: 메모 없는 같은 문서와의 차이 최대 약 115 ms(headless Chromium, 워커 측정). 실제 Orca 프레임은 미측정.
- 한 문단에 메모 6,000개: 조회 60.5 ms, 1,320개를 돌려주고 4,680개는 `missing-memo`로 알림. 위치 찾기는 느려서(1,000개에 24초) 화면은 나누어 찾고 에이전트는 10초에서 멈춰 남은 수를 알린다.

## 위험과 확인하지 못한 것

- **한컴에서 만든 실제 메모 문서로 확인하지 못했다.** 합성 문서(rhwp 0.9.1로 만든 HWP·HWPX)로만 확인했다. 한컴이 쓰는 필드(`%unk`, 명령 `MEMO/…`)와 순서가 다르면 달라질 수 있다.
- 바탕쪽은 같은 파일을 여러 구역이 쓰면 메모를 한 번만 낸다. 겹친 HWP 메모는 파일에 짝 번호가 없어 확정할 수 없으면 `ambiguous`다.
- 그룹으로 묶인 글상자 안의 메모는 내용만 보여 주고 강조하지 않는다(엔진이 자리를 구별해 주지 못한다). 1×1 칸으로 감싼 표 등 일부 구조는 쪽 번호만 나온다.
- 같은 자리로 보이는 표 칸끼리 글이 모두 같고 커서가 하나를 가리키면 반복 머리 행과 구분하지 못한다.
- 여러 문단에 걸친 메모는 시작 쪽의 부분만 강조한다. 댓글 묶음은 추정이다.
- rhwp 상류에 패치를 제안하지 않았다. 상류 0.9.x에는 메모 API가 있어 엔진을 올리면 이 패치를 빼고 어댑터를 맞춘다.
